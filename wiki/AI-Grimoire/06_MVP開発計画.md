# MVP開発計画

**方針：作り込みすぎない。AIエージェントが動く最小セットに集中する。**

---

## MVPの定義

「AI魔導書エージェントがプレイヤーの詠唱を評価し、次の呪文を自律生成する」が体験できれば十分。

### MVPに含めるもの

- [x] 2D戦闘シーン（1フロア、敵1体）
- [x] HPゲージ
- [x] 魔法発動演出
- [x] 音声入力（マイク）
- [x] AI呪文生成（Gemini API）
- [x] 詠唱評価スコア表示
- [x] リザルト画面（ベスト詠唱 + AI総評）

### MVPに含めないもの

- 複数フロアのローグライク進行
- 多数の敵キャラクター
- 装備・アイテムシステム
- 凝ったグラフィック・演出
- BGM・SE（仮素材でOK）

---

## 開発優先順位

### フェーズ1：ゲーム土台（Unity）

1. **Unityで2D戦闘シーンを作る**
   - プレイヤーキャラ（Sprite）
   - 敵キャラ（Sprite × 1体）
   - HPゲージ（UI）
   - 移動処理（WASD）

2. **キーボード入力で仮呪文発動**
   - スペースキーで魔法発動
   - 固定ダメージ
   - 動作確認に使う

### フェーズ2：AI連携（バックエンド）

3. **呪文データのJSON化**
   - 呪文テキスト、難易度、属性をJSONで管理
   - ゲーム側で読み込めるフォーマット設計

4. **Cloud Run API作成（FastAPI）**
   - `/evaluate` エンドポイント実装
   - `/generate-spell` エンドポイント実装
   - Dockerize + Cloud Runデプロイ
   - GitHub Actionsでの自動デプロイ設定

5. **Geminiで呪文生成**
   - Gemini APIとCloud Runを接続
   - 固定プロンプトで呪文生成できることを確認

### フェーズ3：音声連携

6. **Speech-to-Text連携**
   - Unityのマイク入力を音声データとしてCloud Runへ送信
   - Speech-to-Textで認識テキストを返す
   - 認識結果を画面に表示

7. **詠唱ログをFirestoreに保存**
   - セッションIDごとにログ蓄積
   - フロアクリア後のログをAIゲームマスターへ渡す

### フェーズ4：AIゲームマスター起動

8. **リザルト分析とAIゲームマスター判断**
   - フロアクリアログをGeminiに渡して次フロア設定を受け取る
   - セッション終了時のリザルト総評を生成

### フェーズ5：デモ品質への仕上げ

9. **デモ演出強化**
   - 詠唱成功エフェクト（Unity Particle）
   - AI魔導書の読み上げ（Text-to-Speech）
   - リザルト画面のデザイン
   - 30秒デモフローの最終確認

## デモ想定シナリオ（MVP最小版）

1. ゲーム起動 → AI魔導書が呪文を読み上げ
2. プレイヤーが声で詠唱 → 評価スコアが表示
3. 魔法発動 → 敵にダメージ
4. 敵を倒す → リザルト画面
5. ベスト詠唱 + AI総評を表示
