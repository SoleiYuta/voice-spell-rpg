# リポジトリアーキテクチャ思想

## 確定構成

```
voice-spell-rpg/
├── wiki/         人間が読む
├── ai-context/   AIに食わせる知識ベース
├── unity/        実装
├── backend/      実装
└── AGENTS.md     開発ルール
```

---

## wiki/ と ai-context/ を分ける理由

人間向けの仕様と、AI向けの参照資料は**肥大化速度が全然違う**。
分けないと崩壊する。

| ディレクトリ | 読む主体 | 内容 |
|---|---|---|
| `wiki/` | 人間 | MVP仕様・実装順・API仕様・SpellResult・onboarding |
| `ai-context/` | Claude Code / Codex / 将来のAIエージェント | Unity AI research・MCPパターン・CLAUDE.md設計・AI failure patterns |

この分離により：
- 人間 / Claude Code / Codex / 将来のAIエージェント の責務が明確に分かれる
- wiki/ が実装者にとって読みやすいまま維持できる
- AI向け資料が増えても wiki/ が汚染されない

---

## ai-context/ の拡張方針

現在は `ai-context/unity/` のみ。
将来は以下に拡張可能にしておく (今すぐやらない):

```
ai-context/
├── unity/       Unity AI research (現在)
├── backend/     FastAPI / Cloud Run パターン
├── prompts/     プロンプトテンプレート集
├── workflows/   開発ワークフロー定義
└── research/    その他技術調査
```

---

## wiki/AI-Grimoire/ について

現在は codename フェーズなので `AI-Grimoire/` のまま維持。
正式タイトル決定後に `wiki/project/` へ rename 検討。

---

## スケール耐性

この構成は以下に対応できる:
- チームメンバーが増える
- AI エージェントの種類が増える (Claude / Codex / 将来モデル)
- 実装フェーズが進む (unity/ backend/ に実コードが入る)
- ai-context/ のナレッジが蓄積される
