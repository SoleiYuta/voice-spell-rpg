# リザルト診断設計（/result + 診断カード）

ゲーム終了時に「AI魔導書がプレイヤーの声のキャラを**見抜いて煽る**」体験の設計。

> **位置づけ：これは診断・エンタメ（おみくじ/煽りオラクル）。学習用・ボイトレではない。**
> 矯正アドバイスは出さない。精度を約束しない。ただし**実際の行動・数値に紐づける**ことで“見抜かれた感”を出す。

---

## 1. 設計の核（“適当な診断”を避ける唯一のルール）

❌ やらない：Geminiに全データを渡して「自由に診断して」 → それっぽい人格を捏造 → 占い化・適当化
✅ やる：**タイプはコードが実測値から機械的に確定** → Geminiは**煽り文の味付けだけ**

これにより、薄いデータでも「タイプの根拠」が常にデータ側にあり、適当感が消える。

---

## 2. タイプ確定ロジック（コードで決定）

セッション全詠唱を集計し、2軸で4タイプに分類（複数回詠唱でブレを減らす）。

- **声量軸**：`volume`（RMS由来 loud/normal/quiet）の最頻値
- **安定軸**：`completion_rate` と `hesitation_count` から「キレイ / 雑」を判定
  - 例：平均 completion_rate ≥ 0.9 かつ 合計 hesitation ≤ 1 → キレイ、それ以外 → 雑

| | 完走キレイ | 詰まり多い（雑） |
|---|---|---|
| **声デカい（loud）** | `loud_clean` 正統派の大魔導士 | `loud_messy` 勢い任せの暴れ詠唱 |
| **声小さい（quiet）** | `quiet_clean` 囁きの暗殺者 | `quiet_messy` 自信なき見習い |

- `normal` 音量はキャラが薄いので、より極端な軸へ丸める or 中庸タイプ `steady` を別途用意してよい。
- **タイプはここで一意に決まる**（Geminiは決めない）。

## 3. ベスト詠唱（計算で一意）

- セッション中で **最高 `spell_power` のフロア**を選ぶ。`spell_text` と `spell_power` を保持。
- ここは完全にデータ駆動なので“適当”要素ゼロ。

---

## 4. Geminiの役割（味付けのみ）

- **入力**：確定したタイプ名 + 実測サマリ（平均音量・合計詰まり・平均一致率・ベスト詠唱）+ **観測された具体的事象**（例：「floor2で2回噛んだ」）
- **出力**：煽り診断文 1〜2文（50〜80字）
- **必須ルール**：
  - **観測した行動・数値を必ず引用する**（「さっき2回噛んだろ」）＝本人が体感した事実 → “見抜かれた感”
  - **捏造の人格を出さない**（「お前は内向的だ」など体感と紐づかない断定は禁止）
  - **矯正アドバイスを出さない**（「こう直せ」は学習用になるためNG）
  - トーン：皮肉屋の魔導書精霊（既存 `gm_comment` と同キャラ）

プロンプト方針（例）：
```
あなたは皮肉屋の古代魔導書。プレイヤーの詠唱セッションを総評する。
確定タイプ: {type_name}
実測: 平均音量={avg_volume} / 詰まり合計={total_hesitation} / 平均一致率={avg_match_rate}
ベスト詠唱: 「{best_spell_text}」(威力{best_spell_power})
観測事象: {events}   # 例: floor2で2回噛んだ
→ 上の「観測事象」と数値を必ず引用し、50〜80字で煽れ。性格の捏造・改善アドバイスは禁止。
```

---

## 5. `/result` レスポンス（更新版・snake_case厳守）

```json
{
  "session_id": "abc-123",
  "type_key": "loud_messy",
  "type_name": "勢い任せの暴れ詠唱",
  "best_floor": { "floor_id": "floor-2", "spell_text": "...", "spell_power": 1.85 },
  "ai_verdict": "さっき2回噛んだろ。声量は一流だが詠唱は三流だ。",
  "stats": { "avg_volume": "loud", "total_hesitation": 4, "avg_match_rate": 0.78 }
}
```

> 既存 [[tech/API設計]] の `/result`（strong_style/weak_style/ai_review）を、上記の `type_key`/`type_name`/`ai_verdict` ベースに整理する。

---

## 6. フロント：診断カード（[#18] ResultScreen を改）

- **統計表は作らない**。**カード1枚**で出す：
  - `type_name`（でかく）＋ アイコン/色
  - `ai_verdict`（煽り文）
  - ベスト詠唱の `spell_text`（＋余裕があれば音声再生）
- **スクショ映え・配信で貼りたくなる**デザインを優先（VTuberターゲット）

---

## 7. やらないこと（明確な禁止）

- Geminiによる自由形式の診断（適当化するため）
- 矯正・改善アドバイス（学習用になるため）
- 体感と紐づかない性格付け（占い化するため）
- 「科学的分析」「正確な評価」を名乗ること（精度を約束しない）
